## 1.7 Автообработка апдейтов и broadcast правки/удаления

Состояние на 2026-10-14: исправлено. В приложении-i2tech пользователь правил сообщение в MAX, а в ленте оставался старый
текст; причина — `message_edited` не несёт верхнего `message_id`, идентификатор лежит только в
`message.body.mid`, и `findByMaxMessageId()` читал пустой `$update->messageId`, поэтому правка молча пропадала. Правки и
удаления вообще не доезжали до открытой ленты без `wire:poll`. Пользователь решил: плагин обрабатывает апдейты сам (по
конфигу, по умолчанию включено), правка/удаление рассылаются broadcast-событиями, а дублирование с собственным
слушателем приложения снимается идемпотентностью `storeIncoming()`.

- [x] `findByMaxMessageId()`: идентификатор берётся как `$update->messageId ?? $update->message?->body?->mid`;
- [x] `createMessage()`: идемпотентность по паре «`max_chat_id` + `message_id`» (без `message_id` — как раньше);
- [x] `Events\MaxMessageUpdated` (`chat-message.updated`), `Events\MaxMessageDeleted` (`chat-message.deleted`,
  идентификаторы вместо модели), `Events\MaxMessagesCleared` (`chat-message.cleared`) и `Events\MaxChatRemoved`
  (`chat-removed`) + dispatch из соответствующих методов сервиса;
- [x] `Listeners\HandleIncomingMaxUpdate` (шесть типов: `message_created`, `message_edited`, `message_removed`,
  `dialog_cleared`, `dialog_removed`, `chat_title_changed`; `message_callback` не обрабатывается) + регистрация в
  `boot()` при `updates.auto_handle`;
- [x] методы `MaxMessageService`: `applyIncomingClear()` (чистка без MAX API), `applyIncomingChatRemoval()` (статус
  Removed, история и вложения сохраняются), `applyIncomingTitle()` (только известный чат, пустое значение игнорируется);
- [x] ключ `updates.auto_handle` в `config/filament-max-chat.php` и `FILAMENT_MAX_CHAT_UPDATES_AUTO_HANDLE` в

- [x] Echo-подписчик на `updated`/`deleted`/`cleared` → Livewire `chat-reload` (полная перезагрузка ленты), на

**2026-10-14.** Плагин берёт ведение истории на себя (ключ `updates.auto_handle`, по умолчанию включён), а не оставляет

пара. Правка и удаление рассылаются отдельными broadcast-событиями (`chat-message.updated`/`deleted`), а открытая лента
на них перечитывается целиком (`chat-reload`), потому что `appendNewMessages()` дописывает только новые строки и не
отражает изменение или исчезновение уже показанных. `MaxMessageDeleted` несёт идентификаторы, а не модель — к моменту
доставки строка уже удалена. В `message_edited` идентификатор берётся из `message.body.mid` с фолбэком от верхнего
уровня: в спеке MAX верхнего `message_id` у этого апдейта нет. Релиз — целевой номер v1.1.6 (решение пользователя:
партия изменений только начата, версия выбрана заранее; формально смена поведения по умолчанию тянет на минор —
вернуться к вопросу перед релизом), в него же входит ранее выпущенная правка поиска PostgreSQL.
