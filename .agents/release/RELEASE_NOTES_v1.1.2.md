# v1.1.2

Патч исправляет отображение чатов оператора: аватар группы и канала берётся из иконки самого чата, а входящее сообщение
в группе подписывается своим отправителем. Ломающих изменений нет — правки только в слое отображения и в подгрузке
профилей.

## Что было сломано

В группе и канале вместо картинки чата показывался аватар собеседника, а если собеседника в реестре не было, картинка
пропадала вовсе. Причина: плагин везде брал аватар через `interlocutor()`, тогда как у группы и канала картинка — это
иконка чата `max_chats.icon_url` из `getChat()`.

В группе все входящие сообщения подписывались одним и тем же собеседником. `MaxMessageService::storeIncoming()` пишет
`user_id` отправителя самого сообщения, но представление брало отправителя из чата
(`$message->maxChat?->interlocutor()`), то есть первого человека чата, а не автора конкретного сообщения.

## Новое

**Аватар из правильного источника.** `MaxChat::avatarUrl()` и `MaxChat::fullAvatarUrl()` возвращают для группы и канала
непустой `icon_url`, а для диалога — аватар собеседника (`full_avatar_url ?? avatar_url`). Список диалогов, шапка и
карточка чата берут изображение из этих методов; при отсутствии картинки остаётся инициал, как раньше.

**Автор каждого входящего сообщения.** Добавлена связь `MaxMessage::sender()` (по `user_id` самого сообщения, модель
пользователя из конфига `laravel-max-client`) и метод `MaxMessage::senderName()`. Для исходящих сообщений имя не
выводится, для входящих берётся имя отправителя, а при его отсутствии — подпись по типу чата
(`MaxChat::senderFallbackName()`). В группе и канале имя отправителя показывается внутри пузыря. `MaxMessageService`
грузят `['maxChat', 'sender']`, поэтому подписи не вызывают запрос на каждую строку ленты.

**Профили всех участников.** `ChatProfileRefresher` и `RefreshChatProfilesJob` обновляют профили всех не-бот участников
чата, а не только единственного собеседника: в группе и канале у каждого отправителя свой профиль, иначе аватары просто
не подтянулись бы. Боты из обновления исключены.

Кеш-бюстинг к URL аватара не добавляется: при смене самого URL браузер покажет новое изображение, а добавление параметра
могло бы сломать подписанные ссылки.

## Изменение (BC)

Ломающих изменений нет: публичные сигнатуры, ключи и значения по умолчанию конфига, имена и состав ключей переводов не
менялись. Новых переменных окружения нет, `.env.example` и `config/filament-max-chat.php` не требуют правок. Обновление
поведения затрагивает только отображение; порядок обновления установки прежний — `php artisan migrate`, затем
`php artisan max-chat:upgrade` (при переходе со схемы v1.0.x).

## Затронутые сценарии

- Группа и канал: в списке, шапке и карточке показывается иконка чата; входящие сообщения подписаны своим отправителем.
- Диалог: поведение не изменилось — аватар собеседника, подпись отправителя без изменений.
- Чат без собеседника в реестре: картинка группы или канала есть из `icon_url`, инициал используется только при её
  отсутствии.
- Подгрузка профилей: очередь обновляет всех не-бот участников активного чата; при этом профиль собеседника в группе
  может отсутствовать без потери изображения чата.
