# v1.0.7

## Переименование кластеров под `laravel-max-client` v1.1.0

Пакет `geekcodev/laravel-max-client` в версии 1.1.0 переименовал реестр чатов: модель `BotChat` → `MaxChat`, таблица
`max_bot_chats` → `max_chats`, enum `BotChatStatus` → `MaxChatStatus`. Плагин приведён в соответствие:
весь кластер `Chat*` переименован в `Max*`, а конфиг-ключ модели диалога заменён с `bot_chat_model` на `chat_model`.

Внешние ключи и JSON-контракты тоже переименованы: колонка `bot_chat_id` в `max_chat_messages` теперь `max_chat_id`, а
поле payload счётчика непрочитанного — `latest_max_chat_id` вместо `latest_bot_chat_id`. При обновлении существующей
установки перенесите данные реестра и переименуйте внешний ключ по инструкции в README («Обновление с v1.x»).

Это breaking change публичного API: host-приложения должны обновить импорты (`BotChat` → `MaxChat`,
`ChatMessageService` → `MaxMessageService` и т.д.).

## Аватары и профили пользователей

Раньше в апдейтах MAX аватар не приходит, и аватары в списке диалогов и в открытом чате не показывались. Теперь плагин
фоново подгружает профиль пользователя через `MaxUserProfileService` клиента (`getChatMembers`): при открытии чата и для
списка бесед `ChatProfileRefresher` решает, кому это нужно (не чаще, чем раз в `cache_ttl`), и ставит в очередь
`RefreshChatProfilesJob`. Сам UI при этом не блокируется — аватар появляется после фоновой подгрузки. Управляется блоком
`profile.*`; при `profile.enabled=false` вызовы к API полностью отключены.

## Ссылка на конкретный чат

На страницу чата можно вести прямую ссылку с других страниц проекта: `/admin/chat?chat_id=<id чата в MAX>` открывает
конкретный диалог (плагин сам находит запись реестра по `chat_id`). Прежний способ по внутреннему ID записи
(`?chat=<id max_chats>`) сохранён для обратной совместимости. Если `chat_id` не найден — страница открывается как
обычно, без активного диалога.

## Удаление чата из списка

Добавлена кнопка «Удалить чат» (в шапке активного диалога, рядом с «Очистить историю»). В отличие от очистки истории,
действие помечает запись реестра статусом `removed` — диалог исчезает из списка оператора, а история сообщений
сохраняется. Если пользователь снова напишет, `storeIncoming` вернёт записи статус `active` — чат снова появится в
списке, и оператор не пропустит обращение.

## Конфигурация

Новые опции в `config/filament-max-chat.php`:

| Ключ                       | Что делает                                           | По умолчанию |
|----------------------------|------------------------------------------------------|--------------|
| `chat_model`               | Модель диалога (вместо `bot_chat_model`)             | `MaxChat`    |
| `profile.enabled`          | Включить фоновую подгрузку профилей/аватаров         | `true`       |
| `profile.prefetch`         | Когда подгружать: `on_open` / `on_list` / `both`     | `both`       |
| `profile.cache_ttl`        | Не перезапрашивать профиль одного пользователя (сек) | `86400`      |
| `profile.refresh_existing` | Обновлять ли профиль, если аватар уже заполнен       | `false`      |
