# Фильтры email-уведомлений о непрочитанных

## Проблема

Email-дайджест поднимал оператора на любое непрочитанное входящее, включая служебные команды бота (`/start`, `/help` и
т. п.), спам и рекламные сообщения. Из-за этого важные обращения терялись среди шума, а команды сканировались каждую
минуту.

## Решение

В `email.filters` добавлены три настройки:

- `ignore_commands` — команды (без слэша, регистр не важен, суффикс `@bot` отбрасывается), которые всегда пропускаются.
  По умолчанию `start,help,menu,settings,stop,cancel,back`; пустой список отключает фильтр команд.
- `allow_commands` — если непусто, команды вне списка тоже пропускаются; обычный текст эти списки не трогают.
- `ignore_patterns` — wildcard-маски Laravel (`*`, регистр не важен) для спама и ссылок, например `*http*`.

`UnreadChatNotifier` делит сообщения чата на важные и отфильтрованные. Отфильтрованные помечаются `notified_at`, не
сканируются повторно и остаются в ленте и счётчике непрочитанного. В письмо попадают только важные сообщения: count и
превью считаются по ним, поэтому `/start` после реального вопроса не перекрывает его в дайджесте. Чат только из команд
письма не даёт. Отфильтрованные строки помечаются даже при отсутствии получателей и ошибке почты; важные остаются
непомеченными и повторяются, как раньше.

Настройки доступны через env `MAX_CHAT_EMAIL_IGNORE_COMMANDS`, `MAX_CHAT_EMAIL_ALLOW_COMMANDS`,
`MAX_CHAT_EMAIL_IGNORE_PATTERNS` и через опубликованный конфиг. Для установок со старым конфигом без `filters` код
использует встроенный список команд по умолчанию.

## Тесты

- команда `/start` пропускается и помечается без письма;
- `/StArT@support_bot` распознаётся регистронезависимо;
- пустой `ignore_commands` отключает фильтр;
- `allow_commands` пропускает только разрешённые команды;
- смешанный чат: в письме count 1 и превью реального сообщения, команда в письмо не попадает;
- `ignore_patterns` пропускает спам по ссылке и тексту регистронезависимо.

Итого 413 тестов / 1085 утверждений.

## Нюансы

- Команда распознаётся только в начале текста; `/start` внутри обычного сообщения не считается служебным.
- Отфильтрованные сообщения не отправляются задним числом, если фильтры позже изменят.
- Списки команд заданы и в конфиге, и в коде: старый опубликованный конфиг без ключа `filters` всё равно получает
  безопасный список по умолчанию.
