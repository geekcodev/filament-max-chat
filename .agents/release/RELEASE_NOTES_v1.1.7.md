# v1.1.7

Патч закрывает регрессию «контакт не доходит до чата» из хост-приложения, подхватывает новый функционал ядра и добавляет
opt-in email-дайджест о непрочитанных чатах. Причина регрессии была в ядре: официальная OpenAPI-спека MAX делает
`ContactAttachmentPayload.hash` nullable, а гидрация требовала строку — webhook с контактом без подписи `hash` ронялся
на разборе, контроллер вебхука отвечал 400 `invalid_payload`, и апдейт терялся целиком. Фикс выпущен ядром в v1.1.11,
адаптер синхронизирован в v1.2.3; плагин поднимает пол обеих зависимостей, закрепляет фикс сквозным тестом, использует
новое поле `Attachment::$filename` для настоящего имени файла и при включённом `email.enabled` шлёт операторам
напоминание о непрочитанных сообщениях старше N минут. Ломающих изменений нет.

## Новое

**Пол `geekcodev/max-php-client` ^1.1.10 → ^1.1.11 и `geekcodev/laravel-max-client` ^1.2.2 → ^1.2.3.** Ядро v1.1.11
терпимо к отсутствию/`null` в `hash` входящего контакта (пустой хэш — fail-closed: телефон считается неподписанным,
`ContactVerifier` в адаптере без правок); адаптер v1.2.3 — релиз, синхронизированный с этим ядром (логика адаптера не
менялась). Пол поднят осознанно как минимальная рабочая версия: на ядре 1.1.10 и ниже контакт без `hash` не доходит до
ленты вообще.

**Настоящее имя файла в карточке вложения (`Attachment::$filename`).** Ядро v1.1.11 отдаёт обязательное по спеке поле
`filename` файла — раньше плагин его не использовал, и имя угадывалось из URL скачивания: под служебным
`fd.oneme.ru/getfile?...` оператор видел имя, выведенное из URL, или заглушку `file.bin`. Теперь `MaxAttachmentStore`
передаёт имя из вебхука в `download()`; приоритет имени — sanitized `filename` → имя из URL → заглушка, приоритет
расширения — расширение из `filename` → из URL → по MIME → типовое. Санитизация (OWASP A08): отрезаются компоненты пути
(включая `\`), управляющие символы и значения из одних точек, длина ограничена 255 символами; путь хранения по-прежнему
UUID-based, имя — только метаданные карточки.

**Email-дайджест о непрочитанных чатах (`max-chat:notify-unread`, выключен по умолчанию).** Если оператор не увидел
уведомление в панели или закрыл вкладку, плагин может прислать на почту напоминание о чатах с непрочитанными сообщениями
старше `email.unread_after_minutes` (по умолчанию 5 минут). Команда находит непрочитанные входящие, группирует по чатам
и шлёт получателям дайджест (`UnreadChatsMail`, синхронный `send()`, HTML + text/plain) — по одной строке на чат: имя,
число непрочитанных, превью последнего сообщения и ссылка на открытие диалога. Получатели чата — общий список `email.to`
плюс оператор, последний отвечавший в нём (его email берётся из
`user_model` по `operator_id` последнего исходящего сообщения — привязки «чат → оператор» в реестре адаптера нет).
Напоминание однократное: после успешной доставки хотя бы одному адресату строки помечаются новой аддитивной колонкой
`notified_at`; чат без единого получателя не помечается — попытка повторится, когда адрес появится. Чат, выпавший из
реестра, помечается без письма; ошибка почты логируется без содержимого переписки и попытка повторяется. При
`email.enabled=true` команда сама встаёт в планировщик хоста (`->everyMinute()`), поэтому достаточно стандартного cron
со `schedule:run`; требуется настроенный `MAIL_*` приложения. Включается только env-ключами
`FILAMENT_MAX_CHAT_EMAIL_*`, поведение по умолчанию не меняется. Gotcha 27 в AGENTS.md: `getUrl()` страницы панели в
Filament v5 требует default-панель, и в тестах отсутствие `->default()` маскировалось под конфликт моков.

**Сквозной feature-тест.** `tests/Feature/ContactWithoutHashWebhookTest` проводит контакт без `hash` реальным путём
доставки: сырой JSON вебхука → `WebhookHandler::decode()` ядра → событие `MaxUpdateReceived` → слушатель плагина →
`storeIncoming()` → карточка «имя + телефон» в ленте. Раньше такой webhook терялся ещё на декодировании.

**Gotcha 26 в AGENTS.md.** `Http::fake()` с `sink` отдаёт тело один раз: `Http::response()` создаёт один promise с одним
stream, и `sinkStubHandler` на втором запросе читает его без rewind — второй скачивание на одном фейке получает пустой
файл и отсекается по `size === 0`. Дефект виден только тесту со двумя скачиваниями на одном фейке; лечение —
closure-форма `Http::fake(fn () => Http::response(...))`. Взят на заметку при пяти новых тестах имени файла.

## Изменение (BC)

Ломающих изменений нет: публичные сигнатуры не менялись (`download()` — приватный метод), новые ключи конфига
`email.*` выключены по умолчанию, новый перевод `mail.*` и аддитивная миграция совместимы с patch-релизом. Потребители с
ядром ≥ 1.1.11 и адаптером ≥ 1.2.3 поведения зависимостей не заметят; на версиях ниже Composer предупредит о
несовместимости. Потребители заметят только улучшения: файлы показывают настоящее имя из MAX, а при включённом
`email.enabled` — напоминания о непрочитанных чатах.

## Затронутые сценарии

- Входящий контакт в чат оператора: доходит при любой форме `hash` из спеки (строка, `null`, отсутствие).
- Входящий файл: карточка показывает настоящее имя файла из вебхука и расширение из него; без `filename` — прежнее
  поведение (имя из URL, заглушка).
- Email-уведомления: включаются `FILAMENT_MAX_CHAT_EMAIL_ENABLED=true` (+ `TO` и/или `operator_id` последнего
  ответившего), требуют `MAIL_*` и cron `schedule:run` хоста; выключены по умолчанию — без этих ключей поведение не
  меняется.
- Обновление установки: `composer update geekcodev/max-php-client geekcodev/laravel-max-client`, затем
  `php artisan migrate` (аддитивная миграция `0000_02_000004` — колонка `notified_at`, пустая у существующих строк).
- Отказоустойчивость: если MAX завтра добавит в ответ ещё одно необязательное поле, ядро его разберёт без ронения
  апдейта (случай `hash` — именно такой).
