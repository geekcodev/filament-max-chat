## Проблема

Ядро `max-php-client` и адаптер `laravel-max-client` перешли на v2.0.0: `Update` стал типизированной иерархией, enum
`UpdateType`/`AttachmentType`/`ButtonType` удалены, `Attachment`/`AttachmentRequest` — abstract-базы с подтипами,
`UploadedInfo` стал token-only, `MessageBody::$caption` удалён. Плагин собирался под плоскую модель v1.1.11.

## Решение

- `composer.json`: constraints `dev-new` для ядра и адаптера (из Packagist, path-repositories не используются).
- `HandleIncomingMaxUpdate`: ветвление по подтипам (`MessageCreatedUpdate`, `MessageEditedUpdate`,
  `MessageRemovedUpdate`, `DialogClearedUpdate`, `DialogRemovedUpdate`, `ChatTitleChangedUpdate`).
- `MaxMessageService`: методы принимают конкретные подтипы; `findByMaxMessageId()` получает `chatId`/`messageId`
  параметрами. `$caption` больше нет — правка обновляет только текст.
- `MaxAttachmentStore`: метаданные по типизированным вложениям. Видео сознательно не скачивается (только `type`), как и
  раньше фактически: файл большой, оператору нужен факт вложения.
- `MaxChatSender`: `PhotoAttachmentRequest`, `VideoAttachmentRequest`, `AudioAttachmentRequest`,
  `FileAttachmentRequest`, `InlineKeyboardAttachmentRequest` с `Keyboard`/`RequestContactButton`;
  `UploadEndpoint` → `token` (или `url` для фото).
- Контакт: телефон только из `vcf_info`.

## Тесты

PHPUnit 371/371 (951 assertion). Удалены сценарии, невозможные в типизированной модели: lifecycle без `chat_id`,
вложение с `payload: []`, не-массивный payload, `vcfPhone`-приоритет, fallback на `caption`.

## Нюансы

- `dev-new` — только до выпуска ядра и адаптера; в релизном `composer.json` будет `^2.0`.
- `symfony/*` и `laravel/framework` обновлены — advisories 5 → 0.
- CI зелёный: обе зависимости ставятся из Packagist по `dev-new`.
- Серверная проверка в тестовом проекте не пройдена; релиз плагина отложен.
