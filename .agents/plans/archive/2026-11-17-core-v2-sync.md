# План: синхронизация с ядром и адаптером v2.0.0

Статус на 2026-11-23: код и документация готовы, `max-php-client` и `laravel-max-client` выпущены тегом `v2.0.0`,
`composer.json` переведён на `^2.0`, серверная проверка вебхуков в тестовом проекте пройдена. Остался выпуск самого
плагина `v2.0.0`. Выпускной чек-лист — `plans/2026-11-20-before-v2.0-release.md`.

## Цель

Перевести плагин на типизированные события MAX (`Update` с подтипами), не меняя поведение истории переписки, и
подготовить major-релиз `v2.0.0`.

## Этапы

1. [x] `composer.json`: `dev-new` для адаптера и ядра из Packagist (path-repositories не используются).
2. [x] `HandleIncomingMaxUpdate`: ветвление по подтипам (`instanceof`).
3. [x] `MaxMessageService`: методы принимают конкретные подтипы, `findByMaxMessageId()` — параметры вместо плоского
   апдейта; `$caption` удалён.
4. [x] `MaxAttachmentStore`: метаданные по типизированным вложениям; видео не скачивается (только `type`).
5. [x] `MaxChatSender`: исходящие через `*AttachmentRequest`, `Keyboard`, `RequestContactButton`.
6. [x] Контакт: номер только из `vcf_info`.
7. [x] Тесты: фабрики на подтипах; удалены невозможные сценарии (lifecycle без `chat_id`, `payload: []`, `vcfPhone`,
   `caption`).
8. [x] Документация: README (требования, история), AGENTS (constraints), release notes `v2.0.0`, сессия и журнал.
9. [x] Серверная проверка вебхуков в тестовом проекте: создание, правка, удаление, очистка и удаление диалога, смена
   названия доезжают до ленты на типизированной модели (проверено пользователем 2026-11-23).
10. [x] После выпуска ядра и адаптера: `dev-new` заменён на `^2.0` в `composer.json`, README и AGENTS синхронизированы
    (2026-11-23).

## Нюансы

- `dev-new` — движущаяся цель; допустимо только для предрелизной проверки. С 2026-11-23 не используется: обе зависимости
  выпущены тегом `v2.0.0` и ставятся по `^2.0`.
- CI на `dev-new` был зелёный: обе зависимости ставятся из Packagist.
- Видео сознательно не скачивается: файл большой, карточке достаточно типа вложения.
