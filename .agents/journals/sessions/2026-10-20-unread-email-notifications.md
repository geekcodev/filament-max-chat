# Email-дайджест о непрочитанных чатах

## Проблема

ТЗ пользователя: оператор не увидел уведомление в панели или закрыл вкладку — непрочитанные сообщения пропадают из
видимости. Нужно напоминание на почту о чатах с непрочитанными сообщениями старше N минут (по умолчанию 5), выключенное
по умолчанию: поведение установки без новых ключей не должно меняться.

## Решение

- Миграция `0000_02_000004_add_notified_at_to_max_chat_messages.php` — аддитивная колонка `notified_at` с guards
  `hasTable`/`hasColumn`, без индекса.
- `Services/UnreadChatNotifier`: выборка непрочитанных входящих старше `email.unread_after_minutes`, группировка по
  чатам. Получатели чата — общий `email.to` (после `filter_var`) плюс оператор, последний отвечавший: его email берётся
  из `user_model` по `operator_id` последнего исходящего сообщения, потому что привязки «чат → оператор» в реестре
  адаптера нет. Однократность через `notified_at`: после успешной доставки хотя бы одному адресату строки помечаются;
  чат без единого адресата не помечается — попытка повторится, когда адрес появится; чат, выпавший из реестра,
  помечается без письма (иначе минутный запуск сканировал бы его заново); ошибка почты логируется без содержимого
  переписки, строки остаются непомеченными.
- `Mail/UnreadChatsMail` — синхронный `send()` без очереди, HTML + text/plain blade (в текстовой `{!! !!}`:
  экранирование искажало кавычки); ссылка `Pages\OperatorChat::getUrl(['chat_id' => ...])`; ключи `mail.*` в `lang/ru` и
  `lang/en`.
- `Console/MaxChatUnreadNotificationCommand` (`max-chat:notify-unread`) с авто-регистрацией в планировщике хоста при
  `email.enabled`: `callAfterResolving(Schedule::class)`, проверка конфига в момент разрешения, `->everyMinute()` —
  хосту достаточно cron `schedule:run`.
- Конфиг `email.*` (`enabled` false, `unread_after_minutes` 5, `to` []) и `.env.example`, README (раздел «
  Email-уведомления о непрочитанных чатах», конфигурация, архитектура, история), AGENTS.md §4/§5 и gotcha 27.

## Нюансы

`getUrl()` страницы панели в Filament v5 требует default-панель: без `->default()` в тестовой фикстуре
`NoDefaultPanelSetException` из `urlFor()` маскировался под конфликт моков (risky «did not remove its own error
handlers») — фикстура получила `->default()`, закреплено как gotcha 27 (сначала default-панель, потом моки gotcha 9).
Форма — один дайджест на чат, а не письмо на каждое сообщение: активная переписка не задораживает почту. Релиз остаётся
patch v1.1.7: функция opt-in, дефолты не меняются, прецедент фич в патчах (v1.0.9, v1.1.6).
